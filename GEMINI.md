# Scheme Runtime Go

This is the Go runtime library for the Scheme ORM framework. It provides a
type-safe, generics-based query builder, SQL compiler, and database execution
layer targeting PostgreSQL. The runtime is designed to back code generated by the
Scheme schema compiler.

## Architecture

The codebase follows a strict interface-driven layering:

```
pkg/contract/    → Interfaces and type definitions (the "what")
pkg/orm/         → Query builder and fluent API  (the "how to build")
pkg/grammar/     → SQL compilation engine        (the "how to emit SQL")
pkg/testutil/    → Test infrastructure           (ephemeral Postgres via testcontainers)
examples/        → Generated-code examples and integration tests
```

### `pkg/contract/`

Pure interfaces and value types. No implementation logic. This package defines:

- `SQLCompiler` — translates query state into SQL strings and bind parameters.
- `QueryStateProvider` — read-only view of built query state consumed by compilers.
- `DB` — database connection abstraction (`Query`, `QueryRow`, `Exec`).
- `Where`, `Order`, `Relation` — AST node interfaces for conditions, sorting, and eager loading.
- `Column[Model]` — type-safe column descriptor with cast and typed-slice support.
- `TableMetadata[Model]` — static schema/table/column metadata for a model.
- `Aip160Field` — AIP-160 filter field interface for building WHERE conditions from filter strings.
- `ColumnValue`, `AggregateState`, `PaginateAip158Result` — supporting value types.

### `pkg/orm/`

The `QueryBuilder[Model, Mutator]` is the central type. It implements
`QueryStateProvider` and provides a fluent API for:

- SELECT with column selection, DISTINCT, GROUP BY, HAVING, LIMIT, OFFSET
- WHERE conditions via composable `contract.Where` nodes
- ORDER BY via composable `contract.Order` nodes
- Aggregates (COUNT, SUM, AVG, MIN, MAX)
- CRUD operations: `Get`, `First`, `Insert`, `Update`, `Delete`, `Upsert`
- RETURNING variants: `InsertReturning`, `UpdateReturning`, `DeleteReturning`, `UpsertReturning`
- AIP-160 filter parsing (`WhereAip160`)
- AIP-132 order_by parsing (`OrderByAip132`)
- AIP-158 offset pagination (`PaginateAip158`)
- Relationship eager loading (`With`)

#### Subpackages

- `pkg/orm/where/` — WHERE condition AST nodes: `Basic`, `Between`, `Column`,
  `Date`, `Exists`, `In`, `JSON`, `Nested`, `Null`, `Raw`, `Subquery`.
- `pkg/orm/order/` — ORDER BY AST nodes: `ColumnOrder`, `SubqueryOrder`, `RawOrder`.
- `pkg/orm/column/` — Strongly-typed column wrappers that produce `contract.Where`
  and `contract.Order` nodes: `NumericColumn`, `StringColumn`, `ArrayColumn`,
  `NullableColumn`, `JSONColumn`, `GeoColumn`, `TimestampColumn`, `UUIDColumn`,
  `DurationColumn`, `DecimalColumn`, and nullable variants.
- `pkg/orm/relation/` — Relationship definitions and eager loading:
  `HasOne`, `HasMany`, `BelongsTo`, `BelongsToMany`.
- `pkg/orm/aip160/` — AIP-160 filter tree walker and stack-based evaluator.
  - `pkg/orm/aip160/fields/` — Typed field builders for each `Aip160FieldType`
    (string, numeric, bool, timestamp, duration, decimal, enum, UUID).

### `pkg/grammar/`

The `PostgresGrammar` struct implements `contract.SQLCompiler`. It compiles
query state into PostgreSQL-dialect SQL with positional `$N` bind parameters.

Key implementation files:
- `postgres_select.go` — SELECT, DISTINCT, aggregates, GROUP BY, HAVING, LIMIT, OFFSET
- `postgres_where.go` — WHERE/HAVING clause compilation (recursive for nested conditions)
- `postgres_order.go` — ORDER BY compilation
- `postgres_mutation.go` — INSERT, UPDATE, DELETE, UPSERT with `UNNEST`-based
  bulk parameter binding and RETURNING support

### `pkg/testutil/`

`PostgresContainer` wraps `testcontainers-go` to provide:
- Ephemeral PostgreSQL containers for integration tests
- Template database cloning for fast, isolated per-test databases
- Automatic cleanup

### `examples/`

- `examples/single/` — Single-schema example with models, hydrate/dehydrate
  functions, schema definitions, and a comprehensive integration test suite.
- `examples/multi/` — Multi-schema example demonstrating cross-schema queries,
  tenant relationships, and foreign key cascades.

These directories represent what generated code looks like for consumers of this
runtime.

## Conventions

### Code Style
- Go 1.27+ with generics throughout.
- All exported symbols have GoDoc comments.
- Receiver names are short and consistent (`pg` for PostgresGrammar, `qb` for QueryBuilder).
- Error wrapping uses `->` arrow format: `fmt.Errorf("context -> %w", err)`.

### SQL Safety
- Table and column names are always escaped via `pgx.Identifier{name}.Sanitize()`.
- All user values are bound via positional parameters (`$1`, `$2`, ...) tracked
  by `Parameterized` helper struct.
- Bulk mutations use PostgreSQL `UNNEST(...)` with typed array casts for
  efficient multi-row operations.

### Type System
- `Column[Model]` interface provides `ColumnName()`, `PostgresCast()`,
  `ToTypedSlice()`, and `IsArray()` for type-aware SQL generation.
- Each column type (e.g., `NumericColumn[Model, int64]`) produces correctly typed
  `Where` and `Order` nodes through fluent methods like `.Eq()`, `.Gt()`, `.In()`.

### Testing
- Unit tests sit alongside source files (`*_test.go`).
- Integration tests use `testcontainers-go` with the `PostgresContainer` from
  `pkg/testutil/`. Template DB cloning ensures each test gets an isolated
  database with the schema pre-applied.
- Test suites use `TestMain` for container lifecycle management.

### AIP Integration
- **AIP-160 (Filtering):** Filter strings are parsed via `go.chromium.org/luci`
  into an AST, then walked with an iterative post-order traversal using a stack
  to build `contract.Where` trees.
- **AIP-132 (Ordering):** Order strings are parsed via `go.chromium.org/luci`
  and mapped to `contract.Order` nodes through a column-name lookup map.
- **AIP-158 (Pagination):** Offset-based pagination uses `go.einride.tech/aip`
  for page token encoding/decoding.
