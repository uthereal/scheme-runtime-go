# Rule: Scheme Runtime Go - Architecture & System Design

The Scheme Go runtime library (`scheme-runtime-go`) provides a type-safe, generics-based query builder, SQL compiler,
and database execution layer targeting PostgreSQL. It is engineered specifically to back code generated by the Scheme
schema compiler.

---

## Architectural Layering

The codebase follows a strict interface-driven layering model where abstractions and data flow cleanly between distinct
packages:

```
pkg/contract/    → Interfaces and type definitions (the "what")
pkg/orm/         → Query builder and fluent API  (the "how to build")
pkg/grammar/     → SQL compilation engine        (the "how to emit SQL")
pkg/testutil/    → Test infrastructure           (ephemeral Postgres via testcontainers)
examples/        → Generated-code examples and integration tests
```

---

## Package Responsibilities

### 1. `pkg/contract/` (Interfaces & Type Contracts)

Contains pure interfaces, AST contracts, and supporting value types. It defines no implementation logic or execution
runtime.

- **`SQLCompiler`**: Translates query state (`QueryStateProvider`) into PostgreSQL SQL strings and positional bind
  parameters.
- **`QueryStateProvider`**: Read-only view of built query state consumed by compilers to emit SQL.
- **`DB`**: Database connection abstraction covering `Query`, `QueryRow`, and
  `Exec` operations (compatible with `pgxpool.Pool` and transactions).
- **`Where`**: AST node interface for WHERE/HAVING condition expressions.
- **`Order`**: AST node interface for ORDER BY sorting expressions.
- **`Relation`**: AST node interface for eager loading relationships.
- **`Column[Model]`**: Type-safe column descriptor with cast and typed-slice support (`ColumnName()`, `PostgresCast()`,
  `ToTypedSlice()`, `IsArray()`).
- **`TableMetadata[Model]`**: Static schema, table, and column metadata for a given model.
- **`Aip160Field`**: Field descriptor interface for evaluating AIP-160 filter expressions into `contract.Where` nodes.
- **Value Types**: `ColumnValue`, `AggregateState`, `PaginateAip158Result`.

### 2. `pkg/orm/` (Query Builder & Fluent API)

The `QueryBuilder[Model, Mutator]` is the central type in the runtime. It implements `contract.QueryStateProvider` and
exposes a fluent API for building queries and executing operations.

#### Core Capabilities

- **SELECT**: Column projection, `DISTINCT`, `GROUP BY`, `HAVING`, `LIMIT`, `OFFSET`.
- **WHERE**: Composable filter conditions via `contract.Where` nodes.
- **ORDER BY**: Composable sort expressions via `contract.Order` nodes.
- **Aggregates**: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`.
- **CRUD Operations**: `Get`, `First`, `Insert`, `Update`, `UpdateMany`, `Delete`.
- **Conflict Handling**: `OnConflictUpdate`, `OnConflictDoNothing`.
- **RETURNING Variants**: `InsertReturning`, `InsertManyReturning`, `UpdateReturning`, `UpdateManyReturning`, `DeleteReturning`.
- **AIP-160 Filtering**: `WhereAip160(filter string)`.
- **AIP-132 Ordering**: `OrderByAip132(orderBy string)`.
- **AIP-158 Pagination**: `PaginateAip158(pageSize int32, pageToken string)`.
- **Eager Loading**: `With(relations ...contract.Relation)`.

#### Subpackages

- **`pkg/orm/where/`**: WHERE condition AST nodes:
    - `Basic`: Binary comparison expressions (`=`, `!=`, `<`, `<=`, `>`, `>=`).
    - `Between`: Range boundary checks (`BETWEEN ... AND ...`).
    - `Column`: Column-to-column comparisons.
    - `Date`: Date/time specific condition nodes.
    - `Exists`: Correlated subquery existence checks.
    - `In`: Set inclusion (`IN (...)`, `NOT IN (...)`).
    - `JSON`: JSON/JSONB containment and extraction checks.
    - `Nested`: Logical conjunctions (`AND`, `OR`, `NOT`) grouping child nodes.
    - `Null`: Nullability tests (`IS NULL`, `IS NOT NULL`).
    - `Raw`: Raw SQL condition escape hatch.
    - `Subquery`: Subquery comparisons.
- **`pkg/orm/order/`**: ORDER BY AST nodes:
    - `ColumnOrder`: Column sort expressions with ASC/DESC and NULLS FIRST/LAST.
    - `SubqueryOrder`: Ordering based on evaluated subquery results.
    - `RawOrder`: Raw SQL ordering escape hatch.
- **`pkg/orm/column/`**: Strongly-typed column wrappers generating `contract.Where`
  and `contract.Order` AST nodes via fluent methods (`.Eq()`, `.Gt()`, `.In()`):
    - `NumericColumn[Model, T]`
    - `StringColumn[Model]`
    - `ArrayColumn[Model, T]`
    - `NullableColumn[Model, T]`
    - `JSONColumn[Model, T]`
    - `GeoColumn[Model, T]`
    - `TimestampColumn[Model]`
    - `UUIDColumn[Model]`
    - `DurationColumn[Model]`
    - `DecimalColumn[Model]`
    - Corresponding nullable variants for all scalar types.
- **`pkg/orm/relation/`**: Eager loading and relationship specifications:
    - `HasOne`: One-to-one relationship.
    - `HasMany`: One-to-many relationship.
    - `BelongsTo`: Many-to-one foreign key relationship.
    - `BelongsToMany`: Many-to-many junction-backed relationship.
- **`pkg/orm/aip160/`**: AIP-160 filter expression traversal and evaluation:
    - Parses AST using `go.chromium.org/luci`.
    - Walks the AST with an iterative post-order traversal using a stack.
    - Evaluates nodes into `contract.Where` trees.
    - `pkg/orm/aip160/fields/`: Typed field builders for each `Aip160FieldType`
      (string, numeric, bool, timestamp, duration, decimal, enum, UUID).

### 3. `pkg/grammar/` (PostgreSQL SQL Compilation)

The `PostgresGrammar` struct implements `contract.SQLCompiler`. It compiles built query state into PostgreSQL-dialect
SQL with positional `$N` bind parameters.

#### Key Source Files

- **`postgres_select.go`**: Compiles SELECT, column projections, DISTINCT, aggregate functions, GROUP BY, HAVING, LIMIT,
  and OFFSET clauses.
- **`postgres_where.go`**: Compiles WHERE and HAVING clauses via recursive traversal of nested AST conditions.
- **`postgres_order.go`**: Compiles ORDER BY clauses, collation, and null ordering.
- **`postgres_mutation.go`**: Compiles INSERT (with ON CONFLICT), UPDATE, and DELETE statements. Uses PostgreSQL `UNNEST(...)` with
  typed array casts for bulk parameter binding and compiles `RETURNING` clauses.

### 4. `pkg/testutil/` (Integration Test Infrastructure)

`PostgresContainer` wraps `testcontainers-go` to provide reliable, fast, and isolated database environments for
integration tests:

- Manages ephemeral PostgreSQL container lifecycles.
- Clones a template database with pre-applied migrations/schemas for per-test database isolation without slow schema
  rebuilds.
- Automatic resource teardown and cleanup.

### 5. `examples/` (Consumer Code Patterns)

Provides reference implementations demonstrating code generated by the Scheme schema compiler:

- **`examples/single/`**: Single-schema reference with models, hydrate/dehydrate functions, schema definitions, and
  integration tests.
- **`examples/multi/`**: Multi-schema reference showing cross-schema queries, tenant relationships, and foreign key
  cascades.

## Runtime Engineering Conventions

### SQL Safety & Parameterization

- **Identifier Sanitization**: All table, schema, and column names MUST be sanitized using
  `pgx.Identifier{name}.Sanitize()`.
- **Positional Parameters**: All user values MUST be bound as positional parameters (`$1`, `$2`, ...) tracked by the
  `Parameterized` helper struct.
- **Bulk Mutations**: Multi-row INSERT statements MUST use PostgreSQL `UNNEST(...)` with typed array
  casts for performance and safety.

### Type Safety & AST Generation

- **`Column[Model]` Contract**: Provides `ColumnName()`, `PostgresCast()`,
  `ToTypedSlice()`, and `IsArray()` for type-aware SQL generation.
- **Fluent Column Nodes**: Strongly-typed column wrappers produce validated
  `contract.Where` and `contract.Order` nodes.

### Standard Receiver Names

- `g` for `PostgresGrammar`
- `qb` for `QueryBuilder`
